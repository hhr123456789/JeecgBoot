  ## 业务逻辑说明

  ### 班组用能统计的数据流

  InfluxDB (实时点位数据)
      ↓ (InfluxDBSyncJob 每5分钟同步)
  MySQL 实时表 (tb_equ_ele_data, tb_equ_energy_data)
      ↓ (InfluxDBSyncJob 实时更新统计)
  MySQL 统计表 (tb_ep_equ_energy_daycount/monthcount/yearcount)
      ↓ (班组统计服务)
  班组用能统计 (按班组+时间维度汇总)

  ### 核心数据表

  1. **tb_team_info** - 班组基础信息
     - team_code: 班组编码（唯一）
     - team_name: 班组名称
     - shift_type: 班次类型（早班/中班/晚班/夜班）
     - org_code: 所属组织

  2. **tb_team_dimension_relation** - 班组维度关联（核心）
     - team_code: 班组编码
     - dimension_code: 维度编码（部门编码，如A01B03）
     - dimension_type: 维度类型（1:按部门用电, 2:按线路用电, 3:天然气, 4:压缩空气, 5:企业用水）
     - energy_type: 能源类型（1:电, 2:水, 5:压缩空气, 8:天然气）
     - module_ids: 关联的仪表ID列表（逗号分隔）

  3. **tb_team_shift_schedule** - 班组排班
     - team_code: 班组编码
     - shift_date: 排班日期
     - shift_type: 班次类型
     - start_time: 开始时间
     - end_time: 结束时间
     - work_hours: 工作时长

  4. **tb_module** - 仪表主数据
     - module_id: 仪表编号（统计表关联键）
     - module_name: 仪表名称
     - energy_type: 能源类型
     - sys_org_code: 所属部门（关联sys_depart.id）

  5. **tb_ep_equ_energy_daycount** - 日能耗统计
     - module_id: 仪表编号
     - dt: 统计日期
     - energy_count: 能耗值 (end_count - strat_count)
     - strat_count: 开始值
     - end_count: 结束值
     - energy_price: 能源单价
     - total_count: 总费用
     - zbm_count: 折标煤值
     - tpf_count: 碳排放值

  ### 统计逻辑

  班组用能统计需要：
  1. 根据 `tb_team_dimension_relation.module_ids` 找到班组关联的所有仪表
  2. 根据 `tb_team_shift_schedule` 确定班组的工作时间段
  3. 从 `tb_ep_equ_energy_daycount` 查询这些仪表在指定时间段的能耗数据
  4. 按班组汇总：能耗值、费用、折标煤、碳排放等

  ## 工作流程

  ### 阶段 1: 全面诊断（3个 Analyst 并行工作）

  **Database Analyst 任务**:
  1. 连接数据库，检查以下内容：
     - `tb_team_info` 是否有班组数据
     - `tb_team_dimension_relation` 是否正确关联仪表
     - `tb_team_shift_schedule` 是否有排班数据
     - `tb_module` 仪表数据是否完整
     - `tb_ep_equ_energy_daycount` 是否有统计数据
     - 检查数据关联关系（team_code, module_id, dimension_code）
  2. 检查 InfluxDB 同步任务日志
  3. 生成数据诊断报告，标注问题

  **Backend Analyst 任务**:
  1. 搜索班组用能统计相关的后端代码
  2. 检查 Controller 接口定义
  3. 检查 Service 业务逻辑实现
  4. 检查 Mapper SQL 查询
  5. 验证数据查询和汇总逻辑
  6. 生成后端问题报告

  **Frontend Analyst 任务**:
  1. 搜索班组用能统计的前端页面
  2. 检查 API 调用代码
  3. 检查数据处理和渲染逻辑
  4. 检查错误处理和提示
  5. 生成前端问题报告

  **输出**: 3份诊断报告提交给 Team Lead 审核
