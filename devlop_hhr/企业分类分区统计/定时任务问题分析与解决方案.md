# 企业分类分区统计定时任务问题分析与解决方案

## 一、问题现象

定时任务 `EnergyClassificationSyncJob` 每5分钟执行一次，但数据库中的 `tb_energy_classification_summary` 表没有生成数据。

## 二、代码架构分析

### 2.1 调用链路

```
EnergyClassificationSyncJob.syncClassificationData()  (定时任务入口)
  ↓
EnergyClassificationSyncJob.syncDateData()  (同步指定日期数据)
  ↓
IEnergyClassificationService.syncByDate()  (服务接口)
  ↓
EnergyClassificationServiceImpl.syncByDate()  (服务实现 - 委托)
  ↓
IEnergyClassificationSyncService.syncByDate()  (同步服务接口)
  ↓
EnergyClassificationSyncServiceImpl.syncByDate()  (同步服务实现)
  ↓
EnergyClassificationSyncServiceImpl.syncClassificationData()  (核心同步逻辑)
  ↓
TbEnergyClassificationSummaryMapper.selectStatisticsGroupByOrgAndEnergyType()  (SQL查询)
```

### 2.2 核心SQL查询逻辑

定时任务通过以下SQL从实时表聚合数据：

```sql
SELECT
    m.sys_org_code as org_code,
    m.energy_type,
    DATE(d.dt) as stat_date,
    DATE_FORMAT(d.dt, '%Y-%m') as stat_month,
    DATE_FORMAT(d.dt, '%Y') as stat_year,
    COALESCE(SUM(d.energy_count), 0) as total_consumption,
    COALESCE(SUM(d.peak_count), 0) as peak_consumption,
    COALESCE(SUM(d.level_count), 0) as flat_consumption,
    COALESCE(SUM(d.valley_count), 0) as valley_consumption,
    COALESCE(SUM(d.cusp_count), 0) as cusp_consumption,
    COUNT(DISTINCT d.module_id) as meter_count
FROM tb_ep_equ_energy_daycount d
INNER JOIN tb_module m ON d.module_id = m.module_id
WHERE m.isaction = 'Y'
AND d.dt >= #{startDate}
AND d.dt <= #{endDate}
GROUP BY m.sys_org_code, m.energy_type, DATE(d.dt)
ORDER BY m.sys_org_code, m.energy_type, DATE(d.dt)
```

### 2.3 分类与仪表的对应关系

**关键点**：
- **分类（部门）** 通过 `tb_module.sys_org_code` 字段确定
- **能源类型** 通过 `tb_module.energy_type` 字段确定
- 每个仪表（module）必须有 `sys_org_code` 和 `energy_type` 属性
- 定时任务按 **部门编码 + 能源类型 + 日期** 进行分组聚合

**示例**：
- 仪表A：`module_id=M001`, `sys_org_code=A01-01`, `energy_type=1` (电能)
- 仪表B：`module_id=M002`, `sys_org_code=A01-01`, `energy_type=2` (水能)
- 仪表C：`module_id=M003`, `sys_org_code=A01-02`, `energy_type=1` (电能)

定时任务会生成以下分类统计记录：
1. `org_code=A01-01`, `energy_type=1` (一号车间的电能消耗)
2. `org_code=A01-01`, `energy_type=2` (一号车间的水能消耗)
3. `org_code=A01-02`, `energy_type=1` (二号车间的电能消耗)

## 三、可能的问题原因

### 3.1 数据源问题

1. **实时统计表无数据**
   - `tb_ep_equ_energy_daycount` 表可能没有数据
   - 或者数据的时间范围不在定时任务查询的范围内

2. **仪表表配置问题**
   - `tb_module.isaction != 'Y'` (仪表未启用)
   - `tb_module.sys_org_code` 为 NULL 或空字符串 (缺少部门编码)
   - `tb_module.energy_type` 为 NULL (缺少能源类型)

3. **数据关联问题**
   - `tb_ep_equ_energy_daycount.module_id` 与 `tb_module.module_id` 无法关联
   - 实时表中的 `module_id` 在仪表表中不存在

### 3.2 定时任务逻辑问题

1. **时间范围计算错误**
   - 定时任务查询的是"前一日"和"当日"的数据
   - 如果实时表的数据时间戳不在这个范围内，就查不到数据

2. **数据同步前被清理**
   - `syncClassificationData` 方法会先调用 `cleanupOldData` 清理旧数据
   - 如果清理逻辑有问题，可能会误删数据

3. **事务回滚**
   - 同步方法使用了 `@Transactional` 注解
   - 如果过程中有异常，整个事务会回滚，导致数据未保存

### 3.3 定时任务执行问题

1. **定时任务未启动**
   - Spring Boot 主类可能没有添加 `@EnableScheduling` 注解
   - 定时任务被禁用

2. **定时任务执行但有异常**
   - 异常被捕获但未正确处理
   - 日志级别设置不当，看不到错误信息

private void syncDateData(Date targetDate, String dateDesc) {
    try {
        log.info("========== 开始同步{}的数据 ==========", dateDesc);
        log.info("目标日期: {}", targetDate);

        // 检查是否存在未同步的数据
        boolean hasUnsyncedData = energyClassificationService.hasUnsyncedData(targetDate);
        log.info("是否存在未同步数据: {}", hasUnsyncedData);

        if (hasUnsyncedData) {
            log.info("发现{}存在未同步数据，开始同步: {}", dateDesc, targetDate);

            Map<String, Object> result = energyClassificationService.syncByDate(targetDate);

            String status = (String) result.get("status");
            log.info("同步结果状态: {}", status);
            log.info("同步结果详情: {}", result);

            if ("SUCCESS".equals(status)) {
                int successCount = (Integer) result.get("successCount");
                int failCount = (Integer) result.get("failCount");
                int totalRecords = (Integer) result.get("totalRecords");

                log.info("{}数据同步完成: 成功={}, 失败={}, 总数={}",
                        dateDesc, successCount, failCount, totalRecords);
            } else {
                log.error("{}数据同步失败: {}", dateDesc, result);
            }
        } else {
            log.info("{}数据已是最新，无需同步", dateDesc);
        }

        log.info("========== {}数据同步流程结束 ==========", dateDesc);

    } catch (Exception e) {
        log.error("同步{}数据失败: {}", dateDesc, targetDate, e);
    }
}

### 5.2 修复数据查询逻辑

在 `EnergyClassificationSyncServiceImpl.java` 中增强日志：

```java
@Override
@Transactional(rollbackFor = Exception.class)
public Map<String, Object> syncClassificationData(Date startDate, Date endDate) {
    try {
        log.info("========== 开始同步企业分类分区统计数据 ==========");
        log.info("时间范围: startDate={}, endDate={}", startDate, endDate);

        Map<String, Object> syncResult = new HashMap<>();
        syncResult.put("startTime", new Date());
        syncResult.put("startDate", startDate);
        syncResult.put("endDate", endDate);

        // 1. 先查询是否有数据可以同步
        log.info("步骤1: 查询实时表数据...");
        List<ClassificationStatisticsVO> dailyStats =
            summaryMapper.selectStatisticsGroupByOrgAndEnergyType(startDate, endDate);

        log.info("查询到 {} 条待同步的统计数据", dailyStats.size());

        if (dailyStats.isEmpty()) {
            log.warn("警告: 未查询到任何待同步的数据！");
            log.warn("请检查:");
            log.warn("1. tb_ep_equ_energy_daycount 表是否有数据");
            log.warn("2. tb_module 表中仪表是否启用 (isaction='Y')");
            log.warn("3. tb_module 表中仪表是否有 sys_org_code 和 energy_type");
            log.warn("4. 时间范围是否正确: {} 到 {}", startDate, endDate);

            syncResult.put("successCount", 0);
            syncResult.put("failCount", 0);
            syncResult.put("totalRecords", 0);
            syncResult.put("status", "NO_DATA");
            syncResult.put("message", "未查询到待同步的数据");
            return syncResult;
        }

        // 2. 清理指定时间范围内的旧数据
        log.info("步骤2: 清理旧数据...");
        Map<String, Object> cleanupResult = cleanupOldData(startDate, endDate);
        log.info("清理结果: {}", cleanupResult);
        syncResult.put("cleanupResult", cleanupResult);

        // 3. 按日期聚合并保存数据
        log.info("步骤3: 保存统计数据...");
        int successCount = 0;
        int failCount = 0;
        int totalRecords = 0;

        for (ClassificationStatisticsVO stat : dailyStats) {
            try {
                log.debug("处理统计记录: orgCode={}, energyType={}, statDate={}, totalConsumption={}",
                         stat.getOrgCode(), stat.getEnergyType(), stat.getStatDate(), stat.getTotalConsumption());

                // 保存统计数据
                boolean saved = saveStatisticsRecord(stat, "day");
                if (saved) {
                    successCount++;
                    log.debug("保存成功");
                } else {
                    failCount++;
                    log.warn("保存失败");
                }
                totalRecords++;
            } catch (Exception e) {
                log.error("保存统计记录失败: orgCode={}, energyType={}",
                         stat.getOrgCode(), stat.getEnergyType(), e);
                failCount++;
            }
        }

        syncResult.put("successCount", successCount);
        syncResult.put("failCount", failCount);
        syncResult.put("totalRecords", totalRecords);
        syncResult.put("endTime", new Date());
        syncResult.put("status", "SUCCESS");

        log.info("========== 同步企业分类分区统计数据完成 ==========");
        log.info("成功: {}, 失败: {}, 总数: {}", successCount, failCount, totalRecords);

        return syncResult;

    } catch (Exception e) {
        log.error("========== 同步企业分类分区统计数据失败 ==========", e);

        Map<String, Object> errorResult = new HashMap<>();
        errorResult.put("startTime", startDate);
        errorResult.put("endDate", endDate);
        errorResult.put("status", "FAILED");
        errorResult.put("errorMessage", e.getMessage());
        errorResult.put("endTime", new Date());

        return errorResult;
    }
}
```

### 5.4 添加手动触发接口

在 Controller 中添加手动触发接口（如果还没有的话）：

```java
@RestController
@RequestMapping("/energy/classification")
public class EnergyClassificationController {

    @Autowired
    private IEnergyClassificationService energyClassificationService;

    /**
     * 手动触发数据同步
     */
    @GetMapping("/syncByDate")
    public Result<?> syncByDate(@RequestParam String targetDate) {
        try {
            SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd");
            Date date = sdf.parse(targetDate);

            Map<String, Object> result = energyClassificationService.syncByDate(date);

            return Result.ok(result);
        } catch (Exception e) {
            log.error("手动触发同步失败", e);
            return Result.error("同步失败: " + e.getMessage());
        }
    }
}
```

## 七、常见问题FAQ

### Q1: 定时任务执行了但没有生成数据？
**A**: 最可能的原因是实时表没有数据，或者仪表表配置不正确。执行诊断SQL检查。

### Q2: 如何确认定时任务是否在运行？
**A**: 查看日志文件，搜索"开始执行企业分类分区统计定时同步任务"。

### Q3: 数据同步后立即被清理了？
**A**: 检查 `cleanupOldData` 方法的逻辑，确保不会误删当前数据。

### Q4: 如何手动触发同步？
**A**: 访问 `/energy/classification/syncByDate?targetDate=2025-01-10` 接口。

### Q5: 定时任务的cron表达式是什么意思？
**A**: `0 */5 * * * ?` 表示每5分钟执行一次。

## 八、总结

定时任务的核心逻辑是：
1. 从 `tb_ep_equ_energy_daycount` (实时表) 读取数据
2. 通过 `tb_module` (仪表表) 获取部门编码和能源类型
3. 按 **部门 + 能源类型 + 日期** 分组聚合
4. 计算费用、碳排放等指标
5. 保存到 `tb_energy_classification_summary` (汇总表)

**关键点**：
- 仪表必须有 `sys_org_code` (部门编码)
- 仪表必须有 `energy_type` (能源类型)
- 仪表必须启用 (`isaction='Y'`)
- 实时表必须有对应时间范围的数据

如果以上任何一个条件不满足，定时任务都不会生成数据。
